# Changelog

Все значимые изменения в проекте YAS-DT документируются в этом файле.

## [2.3.0] - 2026-05-30

### ✨ Excel-подобные мультифильтры графа

**Сферы и теги — теперь множественный выбор**
- Новый компонент `MultiSelect`: выпадающий список с чекбоксами вместо одиночных селектов
- Кнопки «✓ Выбрать все» / «✕ Снять все»
- Множественный выбор значений (логика ИЛИ: узел проходит, если совпадает хотя бы одно)
- Счётчик узлов по каждому значению (как в Excel), цветная точка у сфер
- Поиск внутри списка тегов
- Сводка на кнопке: «все» / «N из M»
- Закрытие по клику вне меню

**Диапазонные фильтры**
- Новый компонент `RangeFilter`: двухползунковые слайдеры по возрасту и весу
- Границы вычисляются из реальных данных, с кнопкой сброса

**Синхронизация UI**
- Легенда сфер тоглит выбор (вкл/выкл, зачёркивание выключенных)
- Клик по `#тегу` в панели деталей изолирует/сбрасывает тег
- Все фильтры работают в связке с поиском

### 🔧 Прочее
- `.gitignore`: игнорируем `*.tsbuildinfo`

## [2.2.0] - 2026-05-28

### ✨ Новая таксономия: сферы HPI + теги

**Концептуально**
- Заменили запутанные `category` (где были смешаны типы знания и контексты) на чёткое разделение:
  - **`sphere`** — одна из 8 сфер жизни HPI (один к одному с фактом)
  - **`tags`** — массив свободных меток из контролируемых словарей (тип, контекст, этап)
- Жизненные этапы (`section`) теперь представлены как теги — иерархия упростилась.

**База данных**
- `facts.sphere TEXT` — 8 сфер: `loved`, `family`, `friends`, `career`, `physical`, `mental`, `hobby`, `wealth`
- `facts.tags TEXT[]` с GIN-индексом для быстрой фильтрации
- SQL-патч: `scripts/add-spheres-tags.sql`

**Авто-классификация**
- Скрипт `scripts/classify-facts.ts` через Gemini Flash Lite
- 196 фактов классифицированы за один проход, бэкап в `data/classifications.json`
- Распределение: career 102, mental 55, family 11, physical/hobby/wealth по 7, loved 4, friends 3

**UI**
- Цвета узлов по сферам HPI (8 цветов вместо 8 категорий)
- Легенда внизу слева с эмодзи и названиями сфер
- Два дропдауна в топ-баре: «Все сферы» и «Все теги»
- Кликабельные `#теги` в панели деталей факта

### 🚀 Производительность графа: масштаб до 1000 узлов

- Физика вынесена в Web Worker (не блокирует UI, прогресс-бар сверху)
- Pan/zoom через `useRef` + прямой `setAttribute` на SVG-группе — без React-ререндеров
- Hover/selected через CSS `:hover` — браузер сам, без `setState`
- Текст с `paint-order: stroke fill` вместо `<rect>`-фонов
- Top-N лейблов по weight на среднем zoom, все на полном
- Раннее отсечение пар > 600px в repulsion → 2-3x ускорение симуляции

### 🎨 Визуализация графа

- Декларативный SVG-рендер (заменил императивный Canvas)
- Force-directed раскладка с одноразовой симуляцией при загрузке
- Кнопки управления масштабом справа внизу: + / ползунок / − / fit-to-screen
- Поиск по названию, фильтр по сфере и тегу

### 📋 Панель деталей узла

- Полный markdown-контент факта (`### заголовки`, `**жирный**`, `- списки`, параграфы)
- Бейдж сферы с цветом
- Кликабельные теги
- Список связей с типами (`related_to`, `influences`, `causes`, …) и навигацией

## [2.0.0] - 2024-05-25

### 🎉 Мажорный релиз: Семантический граф знаний

Полная перестройка архитектуры на основе рекомендаций Gemini AI после ревью v1.0.

### ✨ Добавлено

#### Архитектура
- **Нормализованная схема БД** (`scripts/schema.sql`)
  - Таблица `facts` для узлов графа
  - Таблица `fact_relations` для рёбер графа с типизацией
  - Таблица `categories` для категорий
  - Таблица `sections` для секций
  - Индексы для оптимизации графовых запросов
  - Представление `facts_with_stats` для аналитики

#### Типы связей
- 10 типов семантических связей:
  - `causes` - причинно-следственная связь
  - `influences` - влияние
  - `contradicts` - противоречие
  - `supports` - поддержка
  - `derives_from` - происходит из
  - `applies_to` - применяется к
  - `similar_to` - похоже на
  - `part_of` - часть чего-то
  - `prerequisite_for` - предусловие для
  - `related_to` - общая связь

#### TypeScript типы
- `RelationType` - enum для типов связей
- `FactRelation` - интерфейс для типизированных связей
- `YasFactWithRelations` - факт с типизированными связями
- `Category` и `Section` - интерфейсы для метаданных
- `YasCoreV2Structure` - новая структура данных v2.0

#### Скрипты
- `scripts/migrate-v2.ts` - умная миграция с:
  - Дедупликацией по названию
  - Разрешением коллизий ID
  - Извлечением метаданных
  - Построением типизированных связей
  - Атомарной загрузкой данных
- `npm run db:migrate:v2` - команда для запуска миграции

#### Документация
- `ARCHITECTURE.md` - детальная архитектура v2.0
- `QUICKSTART.md` - быстрый старт для новых пользователей
- `CHANGELOG.md` - этот файл
- Обновлён `README.md` с описанием v2.0
- `.env.local.example` - пример конфигурации

### 🔧 Изменено

#### Типы
- `YasFact.relations` теперь опциональное (для обратной совместимости)
- Добавлены новые поля в интерфейсы
- Улучшена типизация для работы с графом

#### Миграция
- Старый скрипт `migrate.ts` сохранён для legacy
- Новый скрипт `migrate-v2.ts` с улучшенной логикой:
  - Умная дедупликация (только настоящие дубликаты текста)
  - Сохранение уникальных смыслов при коллизии ID
  - Автоматическое определение типа связи
  - Подробное логирование процесса

#### Конфигурация
- Улучшен `.gitignore` (добавлены Next.js, IDE, OS файлы)
- Добавлен `.env.local.example` для быстрого старта

### 🐛 Исправлено

#### Проблемы v1.0
- ❌ Плоские связи `relations: number[]` → ✅ Типизированные `FactRelation[]`
- ❌ Всё в одной таблице → ✅ Нормализованная схема
- ❌ Нет семантики связей → ✅ 10 типов отношений
- ❌ Дубликаты ID с разным содержанием → ✅ Умное разрешение коллизий
- ❌ Настоящие дубликаты текста → ✅ Дедупликация по названию

### 📊 Статистика

- **Фактов**: 163+ узлов графа
- **Связей**: Автоматически извлекаются из legacy-формата
- **Категорий**: 7 (Военный, Технология, Психофизика, и др.)
- **Секций**: 8 (Генезис, Военная академия, Рост, и др.)
- **Типов связей**: 10 семантических типов

### 🚀 Производительность

- Индексы на `source_fact_id`, `target_fact_id`, `relation_type`
- Представление `facts_with_stats` для быстрой аналитики
- Оптимизированные запросы для графовых операций
