# PR Review Response: Переход на Семантический Граф Знаний (v2.2.0)

Привет! Спасибо за крутой, детальный технический аудит архитектуры v1.0. Твои замечания помогли вовремя скорректировать курс и избежать ограничений плоских структур.

Проект полностью переработан и перенесен на Greenfield-контур. Предыдущий аудит проводился по старой ветке `main`. Актуальное рабочее состояние системы развернуто в ветке **`feature/dt-yas-v2.1`** и зафиксировано под релизным тегом **`v2.2.0`**.

Ниже подробно расписано, какие критические точки закрыты, а также даны обоснования сознательных архитектурных отклонений (Design Decisions), принятых в процессе реализации.

---

## 1. Что полностью реализовано и закрыто (v2.2.0)

1. **Ликвидация плоских массивов (`relations`):** Плоское хранение связей внутри тела фактов (`relations: number[]`) полностью удалено из схемы данных.

2. **Реляционный Граф на уровне БД (Supabase / Postgres):**
   Развернута гибридная структура из двух нормализованных таблиц:
   * `facts` — узлы графа (чистый смысл, базовые веса, метаданные);
   * `fact_relations` — ребра графа, жестко связывающие узлы через внешние ключи (`source_fact_id` и `target_fact_id`) с поддержкой каскадного удаления (`ON DELETE CASCADE`).

3. **Двухпроходный скрипт миграции (`scripts/migrate-v2.ts`):**
   Реализован отказоустойчивый парсер легаси-данных. На первом проходе он зачищает текстовые дубликаты, разрешает коллизии ID и импортирует узлы. На втором — собирает распределенные связи и строит из них валидную реляционную сеть ребер.

4. **Графовый API-слой (`app/api/graph/route.ts`):**
   Развернут рабочий Next.js App Router эндпоинт, который сериализует данные из Supabase и отдает фронтенду строго типизированную структуру `{ nodes, edges }`.

5. **Интерактивный UI (Презентационный слой):**
   Реализован рендеринг живой интерактивной топологии сети непосредственно в браузере с использованием SVG. Узлы окрашены по сферам HPI, физика вынесена в Web Worker, размер узлов динамически масштабируется в зависимости от веса. Поддерживаются hover/click, поиск, фильтр по сферам и тегам, pan/zoom с авто-fit.

## 2. Сознательные архитектурные отклонения (Design Decisions)

В процессе заливки монолита мы пошли на несколько стратегических изменений, чтобы сделать систему более гибкой и устойчивой к долгосрочной энтропии:

### 2.1. Мультисферность HPI вместо плоского поля

* **Как просили в ревью:** Оставить поле `hpi_impact_sphere` внутри таблицы `facts`.
* **Как сделано:** Мы пришли к выводу, что один фундаментальный жизненный факт или инсайт редко влияет только на одну изолированную сферу жизни.
* **Решение:** Сейчас на уровне факта зафиксирована **первичная** `sphere` (для цвета узла и быстрой группировки). Полная мультисферная модель `fact_sphere_impact` (M:N с метриками `energy_cost`, `voltage_generation`) — следующая итерация архитектуры, схема описана в roadmap. Это даст корректные радары потенциала без потери размерности.

### 2.2. Динамический семантический инферинг типов связей

* **Как просили в ревью:** Унифицировать легаси-связи под один тип (например, `INFLUENCES`).
* **Как сделано:** Вместо безликих стрелок система использует семантическую типизацию. На этапе миграции функция `inferRelationType()` анализирует контент источника и присваивает один из 10 типов (`causes`, `influences`, `supports`, `prerequisite_for`, `applies_to`, `similar_to`, `contradicts`, `derives_from`, `part_of`, `related_to`). Инфраструктура для перехода к Gemini-инферингу `relation_strength` подготовлена (см. `scripts/classify-facts.ts`, который уже разметил все 196 фактов по сферам и тегам).

### 2.3. Гибкая таксономия: `sphere` + `tags` взамен жесткой `category`

* **Как просили в ревью:** Сохранить плоское поле `category`.
* **Как сделано:** Жесткая привязка к одной категории ограничивает графовый потенциал и аналитику. Мы заменили плоское поле связкой из базового домена (`sphere`) и массива гибких мета-тегов (`tags TEXT[]` с GIN-индексом). Это позволяет группировать, фильтровать и кластеризовать узлы графа в UI по любым срезам (тип знания / контекст / жизненный этап), не перестраивая схему таблиц.
