## 1. Введение и стратегические принципы

### 1.1 Назначение системы

**YAS.hpi.expert** — это автономная, интеллектуальная экосистема управления человеческим потенциалом, смыслами, опытом и стратегическими ресурсами Лидера. Проект является Greenfield-пересборкой платформы `hpi.expert` и переводит плоскую структуру мастер-файла `yas_core.json` в формат семантического графа знаний (Knowledge Graph).

Система предназначена для агрегации неструктурированного потока жизненного опыта (инсайты, контракты, уроки наставников, тактические решения), его автоматической разметки силами ИИ (Gemini API) и визуализации топологии разума в реальном времени через интерактивные фронтенд-интерфейсы.

### 1.2 Базовые метафоры («Строительный BIOS»)

- **Greenfield («Соседний участок»):** Полная изоляция от legacy-кода старой версии платформы. Код v1.0 заморожен и находится на замке в режиме ReadOnly. Строительство ведется на чистой земле по высшим стандартам ИТ-инжиниринга.
- **«Турки строят этажами» (послойный монолит):** Итеративная заливка контуров. Переход к верхнему слою (UI/визуализация) происходит только после достижения 100% стабильности и прочности нижних слоев (БД, API, миграции).
- **«Наследие Строителей» (Принцип №1):** Фокус на создание осязаемых, долговечных и устойчивых к энтропии структур. Отказ от временных «костылей» в пользу масштабируемой гибридной архитектуры.
- **«Семейный Sandbox»:** Выделение изолированного цифрового периметра для Сына (Степана) с целью обучения конфигурации пространства и инжинирингу через модули `ms-coach` и `ROBIUS`.

## 2. Модернизированный технологический стек

Систему переводят на монолитный TypeScript-контур с упором на простоту, надежность и расширяемость.

- **Storage Layer:** Supabase (Cloud PostgreSQL) + реляционная нормализация связей. Плоские массивы `relations` деприоритизированы. При необходимости масштабирования возможна интеграция Apache AGE для нативных графовых запросов Cypher.
- **Application Layer:** Next.js App Router (TypeScript, Node.js). Логика миграции (`scripts/migrate.ts`) и API-эндпоинты (`app/api/twin/route.ts`, `app/api/graph/route.ts`) инкапсулированы в едином проекте.
- **AI Ingestion:** Gemini API Pro (контекст до 2 млн токенов) с обязательной генерацией данных через Structured Outputs / JSON-Schema.
- **Presentation Layer:** Next.js + интерактивные графовые библиотеки (`react-force-graph`, `vis-network`, `D3.js`) для рендеринга топологии сети непосредственно в браузере.

## 3. Спецификация базы данных (Supabase / Postgres)

В новой архитектуре факты становятся узлами графа, а связи — первичными сущностями отдельной таблицы. Это обеспечивает целостность данных, возможность анализа топологии и прозрачную работу с метриками.

### 3.1 Таблица узлов графа — `facts`

```sql
CREATE TABLE facts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(255) NOT NULL,
  content TEXT NOT NULL,
  category VARCHAR(100) NOT NULL,
  section VARCHAR(100) NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  weight NUMERIC(3,2) DEFAULT 1.00,
  status VARCHAR(50) DEFAULT 'active',
  hpi_impact_sphere VARCHAR(100),
  energy_cost NUMERIC(3,2),
  voltage_generation NUMERIC(3,2)
);

CREATE INDEX idx_facts_category ON facts(category);
```

### 3.2 Таблица ребер графа — `fact_relations`

```sql
CREATE TABLE fact_relations (
  id SERIAL PRIMARY KEY,
  source_id INT REFERENCES facts(id) ON DELETE CASCADE,
  target_id INT REFERENCES facts(id) ON DELETE CASCADE,
  relation_type VARCHAR(100) NOT NULL,
  relation_strength NUMERIC(3,2) DEFAULT 1.00,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT unique_source_target_type UNIQUE (source_id, target_id, relation_type)
);

CREATE INDEX idx_relations_source ON fact_relations(source_id);
CREATE INDEX idx_relations_target ON fact_relations(target_id);
```

### 3.3 Принцип хранения данных

- `facts` — узлы знаний, содержащие смысл, категорию, секцию, вес и метрики HPI.
- `fact_relations` — ребра, задающие направленные связи между фактами.
- Каждое ребро определяется типом и весом, что позволяет строить семантическую карту и рассчитывать центральность узлов.

## 4. Слой логики и API (Node.js / Next.js)

### 4.1 Скрипт миграции и нормализации — `scripts/migrate.ts`

Скрипт выполняет:

- парсинг старого файла `data/yas_core.json`;
- декомпозицию плоских данных `knowledge_base` в узлы и ребра;
- нормализацию категорий и секций;
- атомарную запись в Supabase через `facts` и `fact_relations`.

### 4.2 API-эндпоинт графа — `app/api/graph/route.ts`

Эндпоинт должен возвращать сериализованную структуру графа для UI:

```json
{
  "nodes": [
    {
      "id": 1,
      "label": "Наследие Строителей",
      "category": "Психофизика",
      "weight": 0.9
    },
    {
      "id": 204,
      "label": "Гештальт Архитектуры",
      "category": "Расширение системы",
      "weight": 0.9
    }
  ],
  "edges": [
    {
      "id": 1024,
      "source": 204,
      "target": 1,
      "type": "STRENGTHENS",
      "weight": 0.95
    }
  ]
}
```

### 4.3 Аналитические API-запросы

Бэкенд должен поддерживать:

- **K-Hop Neighborhood:** извлечение всех фактов, связанных с выбранным узлом на расстоянии N шагов.
- **Shortest Path:** вычисление кратчайшего пути между двумя ключевыми сущностями.
- **Метрики центральности:** Degree Centrality, Betweenness Centrality, PageRank-подобные оценки.

Эти запросы превращают базу данных в инструмент «мысленного фондового рынка», где важность узла измеряется не только весом, но и позицией в сети.

## 5. Поток данных и AI-инжест (AI Data Ingestion)

При добавлении новой информации через протокол «мягкого ввода» Gemini API должен возвращать расширенный пакет, включающий и новый факт, и структурированные связи.

### 5.1 JSON-схема ответа от Gemini

```json
{
  "new_fact": {
    "title": "Гештальт Архитектуры и Формы",
    "content": "Глубинная любовь к архитектуре зданий, мостов и автодизайну. Стремление к созиданию осязаемых, эстетичных физических форм...",
    "category": "РАСШИРЕНИЕ СИСТЕМЫ",
    "section": "РАСШИРЕНИЕ СИСТЕМЫ",
    "weight": 0.9,
    "metrics": {
      "hpi_impact_sphere": "Самореализация",
      "energy_cost": 0.1,
      "voltage_generation": 0.9
    }
  },
  "inferred_relations": [
    {
      "target_id": 1,
      "relation_type": "STRENGTHENS",
      "relation_strength": 0.9,
      "description": "Эстетика физических форм напрямую усиливает и расширяет базовый BIOS Наследия Строителей."
    },
    {
      "target_id": 72,
      "relation_type": "CALIBRATES",
      "relation_strength": 0.75,
      "description": "Любовь к чистой форме выступает эстетическим фильтром при калибровке эффективности используемых ИТ-инструментов."
    }
  ]
}
```

### 5.2 Обязательные требования к AI

- ответ должен быть строго валидным JSON;
- `new_fact` должен содержать минимальный набор полей для записи в `facts`;
- `inferred_relations` должен содержать корректные `target_id`, `relation_type` и вес;
- связи могут иметь описание, которое помогает построить смысловую трассу в BI.

## 6. Слой визуализации и BI

Фронтенд должен отображать реальную топологию разума, а не статичный список фактов.

### 6.1 Интерактивная топологическая карта

- `Force-Directed Graph` в браузере;
- цвет узла отражает категорию;
- размер узла зависит от его центральности и веса;
- при клике на узел подсвечиваются входящие и исходящие связи.

### 6.2 BI-радары HPI

- нелинейные шкалы по закону Фибоначчи;
- визуализация зон роста, стагнации и дефицита энергии;
- дополнительные метрики: `energy_cost`, `voltage_generation`, `hpi_impact_sphere`.

### 6.3 Телеметрия протокола 8888

- графики энергодефицита ядра;
- автоматическое предупреждение о перегреве системы;
- мониторинг баланса «затрачено / получено» через отношение `energy_cost` к `voltage_generation`.
